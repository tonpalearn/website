ภาพรวมโครงการ

องค์กรไม่ได้ใช้ AI แบบเดียว — ผู้บริหารต้องตัดสินใจ ว่าจะเอา AI ไปวางตรงไหน · พนักงานต้องใช้ให้ได้จริงทุกวัน โดยไม่ทำข้อมูลรั่ว · ทีม IT ต้องสร้างและคุมระบบเองได้ การสอนแบบเดียวทั้งองค์กรจึงไม่ตอบโจทย์ใคร

ข้อเสนอนี้ออกแบบเป็น 4 หลักสูตรแยกตามบทบาท โดยทุกกลุ่มเริ่มจากฐานความเข้าใจเดียวกันก่อน แล้วจึงแยกไปตามความลึกที่แต่ละบทบาทต้องใช้จริง

จุดต่างของข้อเสนอนี้คือผูกเนื้อหาเข้ากับ 2 บริบทจริงของ AUTOCORP — แนวทางการ Deploy AI ในองค์กร (4 โหมด) และ NetSuite ที่องค์กรใช้อยู่ ผู้เรียนจึงไม่ได้เรียน AI ลอย ๆ แต่เห็นเลยว่าเอาไปวางตรงไหนในระบบงานของตัวเอง

🎯 โจทย์
สอน AI แบบเดียวทั้งองค์กร → ผู้บริหารเบื่อเพราะง่ายไป พนักงานงงเพราะยากไป ทีม IT ไม่ได้ของที่เอาไปต่อได้
💡 แนวทาง
ฐานร่วม (Basic) ก่อนเสมอ → แยก 3 เส้นทาง: ตัดสินใจได้ (Executive) · ใช้ได้จริง (Staff) · สร้างและคุมได้ (Developer)
⚙️ ผูกกับระบบจริง
4 โหมด Deploy AI + Governance 6 ข้อ + NetSuite AI (Classic → Generative → Agentic → NetSuite Next) · สอนเชื่อมข้อมูลแบบ บันได 3 ขั้น ที่ใช้ได้ทันทีโดยไม่ต้องรอ NetSuite พร้อม

AutoCorp AI Deployment Model — 4 โหมดการใช้ AI ในองค์กร

กรอบอ้างอิงที่ใช้ตลอดหลักสูตร — ทุกกลุ่มต้องรู้ว่างานที่ตัวเองทำอยู่ในโหมดไหน เพราะแต่ละโหมดมีระดับการควบคุมและความเสี่ยงต่างกัน

โหมดที่ 1
Employee-Initiated Public AI
BYOAI / Public AI
Control: ต่ำRisk: ปานกลาง–สูง
  • พนักงานสมัครและใช้งาน AI ด้วยตนเอง
  • ตัวอย่าง: ChatGPT, Gemini, Claude, Perplexity
  • เหมาะกับ: brainstorming, เขียนงาน, แปลภาษา, research ทั่วไป
  • ใช้ได้เฉพาะข้อมูล Public / Non-sensitive
  • เสี่ยง: Data leakage, Shadow AI
โหมดที่ 2
Enterprise-Sanctioned SaaS AI
Approved Enterprise AI
Control: กลาง–สูงRisk: กลาง
  • บริษัทจัดซื้อ อนุมัติ และกำหนดให้ใช้งาน
  • ตัวอย่าง: Gemini for Workspace, Microsoft Copilot, ChatGPT Enterprise
  • เพิ่ม productivity ในงานเอกสาร ประชุม และวิเคราะห์ข้อมูลทั่วไป
  • องค์กรควบคุมได้ผ่าน SSO, Admin, DLP, Audit Log
  • เสี่ยง: Vendor risk, privacy, data governance
โหมดที่ 3
Enterprise Private Agentic AI
Governed Private Agentic AI
Control: สูงมากRisk: สูง
  • AI Agents บน Private Cloud / ระบบที่บริษัทกำหนด
  • เชื่อม RAG, Knowledge Base, API, Workflow, MCP
  • ทำได้มากกว่า Generate — Reason, Retrieve, Recommend, Execute
  • ต้องมี RBAC, Least Privilege, Human Approval, Audit Trail
  • เสี่ยง: Tool abuse, excessive autonomy, system access
โหมดที่ 4
Application-Embedded AI
ERP-Native / System-Embedded AI
Control: สูงมากRisk: สูง–วิกฤต
  • AI Feature ที่ฝังอยู่ในระบบธุรกิจ เช่น ERP
  • ตัวอย่าง: NetSuite AI / system-native AI features
  • ใช้ข้อมูลในระบบธุรกิจโดยตรง — การเงิน สินค้าคงคลัง ลูกค้า จัดซื้อ
  • ต้องคุมสิทธิ์ธุรกรรม การอนุมัติ และ segregation of duties
  • เสี่ยง: Business impact, transaction error, compliance

Common AI Governance Principles — 6 หลักการร่วม

ใช้ได้กับทุกโหมด สอนเป็นบทปิดใน Class 1 (Basic) และลงรายละเอียดเชิงเทคนิคอีกครั้งใน Class 4 (Developer)

1
Data Classification
จัดประเภทข้อมูลตามความอ่อนไหว และกำหนดการใช้งานที่เหมาะสม
2
AI Registry
ลงทะเบียนและอนุมัติเครื่องมือ/โมเดล AI พร้อมเจ้าของและวัตถุประสงค์
3
Human Accountability
กำหนดความรับผิดชอบของมนุษย์ในการตัดสินใจและผลลัพธ์ที่สำคัญ
4
Security & Access Control
ควบคุมสิทธิ์ตามหลัก Least Privilege และปกป้องข้อมูลตลอดวงจรชีวิต
5
Monitoring & Audit Trail
ติดตามการใช้งาน ตรวจจับความผิดปกติ และบันทึก Audit Trail อย่างต่อเนื่อง
6
Compliance & Risk-Based Governance
ปฏิบัติตามกฎหมาย/มาตรฐาน และบริหารความเสี่ยงตามระดับของข้อมูลและผลกระทบ
🛡️ หลักสำคัญ: ยิ่งข้อมูลอ่อนไหวมากขึ้น + AI มี autonomy มากขึ้น + ผลกระทบทางธุรกิจสูงขึ้น = ต้องมี governance ที่เข้มงวดมากขึ้น

🔌 NetSuite AI Connector Service (MCP)
จุดที่น่าสนใจที่สุดสำหรับ AUTOCORP — เป็นชั้นเชื่อม AI ภายนอก (เช่น Claude) เข้ากับข้อมูล NetSuite ผ่าน MCP ถามเป็นภาษาธรรมชาติได้ ไม่ต้องเขียน integration เอง และทำงานบน security model เดิมของ NetSuite
  • สอนติดตั้งจริงใน Class 4 · Developer
  • ตามเอกสาร Oracle: ไม่กิน AI Units เพราะประมวลผลฝั่ง LLM ของลูกค้า
  • แต่นับรวมใน service concurrency limit — ต้องวางแผนการใช้งานพร้อมกัน
💰 เศรษฐศาสตร์ AI Units

หมายเหตุ: ข้อมูล NetSuite ทั้งหมดในหน้านี้อ้างอิงจากเอกสารนำเสนอของ Oracle NetSuite (ส.ค. 2569) ที่ AUTOCORP ได้รับ — ตัวเลข AI Units เป็น ค่าประมาณสำหรับวางแผน ไม่ใช่การรับประกัน และการเปิดใช้จริงต้องยืนยันกับ Oracle อีกครั้ง
🪜 บันไดการเชื่อมต่อข้อมูล 3 ขั้น — หัวใจของการออกแบบหลักสูตรนี้

เราสอน “รูปทรงของปลั๊ก” ไม่ใช่ “ยี่ห้อของเต้ารับ” — ผู้เรียนจะเข้าใจว่า AI ต่อเข้ากับข้อมูลได้ยังไง ผ่าน 3 ขั้นที่ไล่จาก “ทำได้เลยวันนี้” ไปจนถึง “วันที่ NetSuite พร้อม” ทำให้หลักสูตรไม่ผูกกับว่า NetSuite จะเปิดใช้เมื่อไหร่ — เรียนจบวันนั้นมีของใช้ทันที และวันที่ระบบพร้อม ก็เสียบต่อได้เลยเพราะเข้าใจหลักการเดียวกันมาแล้ว

1
Claude in Chrome — เชื่อมผ่านหน้าจอที่คนใช้อยู่แล้ว
AI ทำงานบนเบราว์เซอร์ด้วย สิทธิ์ล็อกอินของผู้ใช้เอง — อ่านหน้าจอ ดึงข้อมูล กรอกฟอร์ม ตรวจทานข้ามหน้าได้ รวมถึงหน้าจอ NetSuite เอง โดยไม่ต้องเปิด API ไม่ต้องขอสิทธิ์ Admin และไม่ต้องรอ license เพิ่ม · เหมาะกับงานที่คนนั่งทำอยู่แล้วและอยากให้เร็วขึ้น
ใช้ได้วันอบรมไม่ต้องรอใคร
2
MCP — มาตรฐานกลางที่ทำให้ AI ต่อกับระบบไหนก็ได้
สอน MCP (Model Context Protocol) ในฐานะ “ปลั๊กมาตรฐาน” แล้วลงมือต่อจริงกับระบบที่ AUTOCORP เปิดใช้ได้อยู่แล้ว (เช่น Google Workspace, ไฟล์เอกสาร, ฐานข้อมูลภายใน) · ผู้เรียนจะเห็นรูปแบบการเชื่อมครบวงจร — ขอสิทธิ์ → ต่อ → ถามเป็นภาษาคน → ได้คำตอบจากข้อมูลจริง
ใช้ได้วันอบรมไม่ต้องรอ NetSuite
3
NetSuite AI Connector — ปลั๊กตัวเดิม เสียบเข้าเต้ารับ NetSuite
เมื่อเข้าใจขั้น 2 แล้ว ขั้นนี้คือ “ทำซ้ำแบบเดิมกับ NetSuite” — เดินตามขั้นตอนของ Oracle: เปิด Server SuiteScript + OAuth 2.0 → ตั้ง Role permission → ติดตั้ง MCP Standard Tools SuiteApp → สร้าง Integration + Redirect URL → เชื่อม Claude · ถ้าวันอบรมมี Sandbox ให้ทำสด · ถ้ายังไม่พร้อม ส่งมอบเป็น Runbook ที่ทีมกดทำตามเองได้ทันทีวันที่ระบบเปิด

✅ TONPALEARN รับผิดชอบ (ฝั่ง AI)
  • สอนหลักการเชื่อมต่อและ MCP ให้เข้าใจจนต่อเองได้
  • ตั้งค่าและใช้งาน Claude / Claude in Chrome / Claude Code
  • ออกแบบ Agent, Skill, Prompt และ Guardrail

  • สิทธิ์ Administrator และการอนุมัติเปิด Sandbox
  • การตั้งค่าเชิงลึกและแก้ปัญหาเฉพาะทางใน NetSuite
  • นโยบายข้อมูลและการอนุมัติภายในองค์กร
ทำไมออกแบบแบบนี้: TONPALEARN เป็นผู้เชี่ยวชาญด้าน AI Agentic ไม่ใช่ผู้ให้บริการ NetSuite — เราจึงสอนสิ่งที่เราทำได้ดีที่สุดและควบคุมผลลัพธ์ได้จริง คือหลักการเชื่อมต่อที่ใช้ซ้ำได้กับทุกระบบ แล้วส่งมอบ Runbook ให้ทีมไปทำงานร่วมกับคู่ค้า NetSuite ต่อ · ผลคือ ไม่มีโมดูลไหนล่มเพราะระบบยังไม่พร้อม และองค์กรได้ความสามารถที่ติดตัวทีมไป ไม่ผูกกับผู้ขายรายใดรายหนึ่ง
